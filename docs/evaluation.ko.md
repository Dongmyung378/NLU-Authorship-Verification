# 평가 규칙

[English](./evaluation.md) | [프로젝트 개요](../README.ko.md) | [구조](./architecture.ko.md) | [실측 결과](./results.ko.md)

이번 실험은 네 집합의 역할을 분리합니다. 학습 집합은 과제 가중치를 학습하고, 모델 선택 집합은 체크포인트와 모델 정책을 선택합니다. 보정 집합은 출력에 적용할 보정과 판정 기준을 정하며, 최종 평가 집합은 고정한 시스템을 평가합니다. 목표 비율은 70 / 10 / 5 / 15이며, 보고할 실제 개수와 라벨은 저장한 분리 명세와 원본 CSV 해시에서 확인합니다.

## 모델 선택

CE와 직접 구현한 이진 ASL은 고정된 RoBERTa-Large 리비전, 최초 가중치, 토크나이저, seed 378, 학습 기록, 입력 교환 순서, microbatch 2, 유효 배치 32와 최적화 설정을 공유합니다. 독립된 두 worker가 각각 배정된 T4에서 하나의 손실을 학습합니다. 공통 epoch 대기 규칙으로 과제 학습 전에 고정한 최대 6 epoch까지 두 모델이 완료한 epoch 수를 같게 유지합니다. 임계값 0.5에서 원래 순서인 AB의 모델 선택 macro F1이 둘 다 개선되지 않을 때 공통 patience 3을 적용합니다. 어느 하나라도 개선되면 공통 대기 횟수를 초기화합니다. 각 손실은 자신의 최적 체크포인트를 저장하고 정확한 동점에서는 먼저 저장한 epoch를 유지합니다. 선택된 최적 epoch는 달라도 완료한 epoch 수는 같으며, 추론 전에 두 체크포인트를 다시 불러옵니다.

학습 기록만 사용한 처리량 검사를 완료하고 microbatch 2를 유지했습니다. 후보 8의 처리량 배수는 1.0244로 선언한 채택 기준 1.05에 미치지 못했고 32는 더 느렸습니다. 최대 6 epoch의 대응 학습은 실제 경과 9시간과 worker 합산 18시간의 보수적 규칙 안에서 유지합니다. 검사는 예측 기반 검증, 보정이나 최종 평가 추론을 수행하지 않았으며 바뀐 가중치를 모두 폐기했습니다. 측정 원문은 [`throughput-profile.json`](../reports/capability/throughput-profile.json), 별도의 결정 기록은 [`요약`](../reports/capability/throughput-summary.json)에 있습니다. 자원 측정은 과제 성능 결과가 아닙니다.

부모 프로세스는 실제 경과 9시간과 보수적으로 합산한 배정 worker 시간 18시간을 제한합니다. 시간 초과, 한 worker의 실패, 최초 가중치 해시 불일치, 불완전한 공통 epoch 결정이나 유한하지 않은 결과가 있으면 어느 한쪽도 성공한 대응 릴리스로 공개하지 않습니다. 부분 결과는 실패 증거로 보존합니다. FP16 overflow로 건너뛴 update와 성공한 update를 구분하므로, 같은 시도 순서를 성공한 update 수까지 같은 것으로 표현하지 않습니다.

원시 AB의 CE와 ASL 비교는 입력 순서와 임계값 0.5를 같게 유지합니다. 이와 별도로 각 모델의 AB와 logit 평균의 대칭 정책을 비교합니다. 대칭 추론은 macro F1이 0.002 이상 증가하거나, 정확한 입력 순서 불변성을 개선하면서 macro F1 감소가 0.002 이내일 때 선택합니다. 임계값 0.5의 원시 비교에서 우세한 모델도 임시 선택으로 기록합니다. 입력 순서 선택과 원시 비교는 모두 모델 선택 집합만 사용합니다.

CE, custom ASL과 문체 앙상블을 각각 독립적으로 보정한 뒤, 이미 저장한 모델 선택 logits에 각 모델의 고정 temperature와 보정 집합에서 맞춘 임계값을 적용해 배포 모델을 선택합니다. 전체 파이프라인의 모델 선택 macro F1이 보정된 CE보다 0.002 이상 높을 때만 배포할 Large로 custom ASL을 고르며, 그렇지 않으면 CE를 유지합니다. 원시 비교의 선택 모델과 보정된 파이프라인의 선택 모델을 구분해 보고합니다. 모델 선택 집합에서 보정값을 다시 맞추거나 입력 순서 정책을 재선택하지 않으며 추가 GPU 추론도 필요하지 않습니다. 이 증가량에는 손실, 입력 순서와 보정이 함께 반영되므로 손실만의 효과로 볼 수 없습니다. 개선되지 않은 ASL 파이프라인의 결과도 보존합니다.

CE와 custom ASL의 학습 손실은 척도가 다르므로 숫자의 크기만 비교해 성능이나 과적합 감소를 판단할 수 없습니다. 새로운 실험은 Large를 유지하지만 데이터 분리, 과제 초기화, 학습과 출력 보정이 바뀝니다. 따라서 최초 Large 개발 점수와 새로운 고정 평가 점수는 조건을 통제한 전후 성능 비교가 아닙니다. 조건을 통제한 비교는 이번에 새로 학습한 CE와 ASL 사이에서 수행합니다.

## 문체 기반 실험

모든 TF-IDF 어휘와 IDF 값은 학습 집합에서만 맞춥니다. CPU 실험은 XGBoost-LightGBM 설정 4개, 최대 구성 모델 학습 8회와 120분 예산을 선언합니다. 제한된 세 pilot은 전체 특징, TF-IDF 특징만, 문체 특징만 사용하는 경우를 비교하며, 네 번째는 최초의 더 큰 전체 특징 tree 상한을 유지합니다. 구성 모델의 체크포인트는 모델 선택 logloss로 고르고, 앙상블 설정과 가중치는 임계값 0.5의 모델 선택 macro F1으로 결정합니다.

기준은 전체 특징 pilot과 XGBoost 가중치 0.5입니다. 후보가 이를 대체하려면 macro F1이 0.002 이상 증가해야 합니다. 최종 XGBoost 가중치는 0.25, 0.5, 0.75만 허용하며, 0과 1은 구성 모델 진단으로만 보고합니다. 시간 때문에 중단한 후보를 명시하고 필수 기준 학습이 완료되지 않으면 실험도 완료된 것으로 처리하지 않습니다. 저장한 모델을 다시 불러온 점수와 실제 AB/BA 실행이 선택한 앙상블과 일치해야 합니다. 보정과 최종 평가 집합은 이 실험에서 제외합니다.

## 보정

보정 집합의 클래스 간 logit 차이에 temperature scaling을 적용하고 음의 로그 우도(NLL)를 최소화합니다. 선언한 양수 범위 안에서 찾은 temperature가 기본값 1보다 보정 집합의 NLL을 악화시키지 않는 경우에만 적용합니다. 이후 같은 보정 집합에서 macro F1을 기준으로 분류 임계값을 선택합니다. 후보는 서로 다른 보정 점수, 1.0과 0.5입니다. 점수가 정확히 같으면 0.5에 가장 가까운 임계값을, 거리도 같으면 더 작은 임계값을 선택합니다. 최종 평가에서 temperature나 임계값을 다시 맞추지 않습니다.

보정 지표는 NLL, 이진 Brier score와 동일 저자 확률을 같은 폭의 10개 구간으로 나눈 expected calibration error(ECE)입니다. 각 구간에서 평균 확률과 실제 동일 저자 라벨 비율의 절대 차이를 구하고, 구간별 사례 수로 가중 평균합니다. 빈 구간의 기여는 0입니다. 예측 클래스의 confidence를 사용하는 ECE와 정의가 다릅니다. 원시 출력과 보정 출력은 동일한 기록에서 비교하며, NLL이 낮아졌다는 이유만으로 분류 정확도가 높아졌다고 주장하지 않습니다.

별도의 표에서는 분류 임계값으로 선택한 클래스의 confidence를 같은 폭의 10개 구간으로 나눕니다. 각 구간의 사례 수, 정답 수, 실제 정확도와 평균 confidence를 보고하며, 빈 구간의 정확도는 null입니다. 원시 점수는 임계값 0.5, 보정 점수는 고정한 보정 임계값을 사용합니다. 이 표의 정확도는 ECE의 동일 저자 라벨 비율과 다릅니다. 임계값이 0.5가 아니면 선택한 클래스의 confidence가 0.5보다 작을 수도 있습니다.

## 판정 보류

선택적으로 적용할 confidence 임계값은 보정 집합에서 정합니다. Confidence는 분류 임계값으로 선택한 클래스에 부여된 보정 확률로, 동일 저자 판정이면 `p`, 다른 저자 판정이면 `1-p`입니다. 목표는 판정한 비율인 coverage 80% 이상과 판정한 사례의 정확도 90% 이상입니다. 둘을 만족하는 후보 중 coverage가 가장 큰 임계값을 선택합니다. 두 목표를 함께 달성할 수 없으면 요구 coverage를 유지하는 후보 중 보정 정확도가 가장 높은 값을 선택하고, 동점에서는 coverage가 더 큰 값을 선택합니다. 목표를 달성하지 못했다는 사실도 명시합니다. 최종 평가 정확도를 확인한 뒤 목표를 만족하도록 임계값을 조정하지 않습니다.

최종 보고서에는 전체 사례의 정확도와 macro F1, 판정한 개수, 전체 개수, coverage, 판정한 사례의 정확도와 보류한 개수를 함께 제시합니다. 전체 지표와 혼동행렬은 사용자에게 `uncertain`으로 표시한 사례까지 포함해 고정한 이진 예측으로 계산합니다. 판정한 사례의 정확도에서는 보류 사례를 제외하므로 coverage도 함께 공개해야 합니다. 보류는 사용자에게 판정을 내리지 않은 상태이며, 그 자체를 추가 정답으로 계산하지 않습니다.

## 고정과 최종 보고

보정값을 반영해 배포 모델을 선택한 뒤 모든 최종 평가 추론 전에 세 모델 파일, 토크나이저, 파일 목록, 데이터 분리 명세, 학습 설정, 소스 스냅샷, 원시 비교, 배포 선택과 보정된 판정 기준을 함께 고정합니다. 저장된 결과를 다시 사용하거나 복사한 모델을 평가할 때 해시를 다시 확인합니다. 최종 보고서는 고정 기록, 모델, 분리 명세와 소스의 해시를 식별하고 원본 기록 순서의 ID, 정답 개수, 클래스별 개수, 혼동행렬과 예측을 보존합니다.

최종 지표를 확인한 후에는 손실, 입력 순서, 보정 또는 판정 보류 정책을 자동으로 바꾸지 않습니다. 이후 실험을 한다면 규칙과 버전을 구분해야 하며, 이미 확인한 최종 평가 집합을 처음 보는 평가 데이터로 표현할 수 없습니다.

라벨이 없는 원본 `test.csv`와 `live.csv`에서는 예측 파일을 만들 수 있지만 정확도나 F1을 계산할 수 없습니다. 원본 데이터는 과거 개발에서도 사용했고 저자나 도메인 ID가 없습니다. 확인된 범위는 이번 실험의 문서가 분리된 평가 구조이며, 독립적인 새 저자나 도메인에서의 일반화 성능을 뜻하지 않습니다.

## 진단 구간

글 길이 구간은 입력이 잘리기 전, 전처리한 두 글 중 짧은 쪽의 공백 기준 단어 수로 정합니다. 50단어 미만, 50–199단어, 200단어 이상으로 나누고 성능과 함께 각 구간의 개수를 제시합니다. 입력 잘림 비율, AB와 BA의 점수 차이 및 판정 불일치, 대칭 점수의 순서 불변성과 고정 토크나이저에서 실제로 잘린 입력의 중복도 확인합니다.

완료한 [입력 길이 검사](../reports/token-length-audit.json)에서 최종 평가 4,708쌍 중 197쌍(4.184%)이 전체 512토큰 한도를 초과했습니다. 토큰 길이와 짧은 쪽의 단어 수는 서로 다른 입력 특성입니다. 200단어 이상 구간의 최종 평가 사례는 5쌍뿐이므로, 구간 성능에 이 개수를 함께 표시하고 긴 글에 대한 일반화 근거로 해석하지 않습니다. 이 검사는 레이블, 모델 가중치와 예측을 사용하지 않았으며 분할과 모델 선택을 바꾸지 않았습니다.

이 분석은 같은 최종 평가를 구간별로 확인하는 기술적 분석입니다. 오류의 원인을 인과적으로 입증하거나 최종 라벨로 다시 조정할 근거는 아닙니다. 사례가 적은 구간은 변동이 클 수 있습니다. Seed 378 한 번의 실험으로 여러 실행의 불확실성을 추정하거나 특정 손실이 언제나 우수하다고 결론 내리지 않습니다.

## 조건부 불확실성

고정한 계획은 [`scripts/bootstrap_results.py`](../scripts/bootstrap_results.py)의 문서 연결 요소 전체를 사용하는 대응 bootstrap 1,000회, seed 378과 95% percentile 구간을 사전에 선언합니다. 매번 최종 평가 그룹의 원래 개수만큼 복원 표집합니다. 선택된 그룹의 모든 글 쌍을 해당 그룹의 선택 횟수만큼 반복하므로 표집한 글 쌍 수는 달라질 수 있습니다. 세 모델에 같은 표집을 적용하며 지표에서는 글 쌍을 동일하게 가중합니다.

세 고정 파이프라인의 정확도와 macro F1 구간, 보정된 custom ASL에서 CE를 뺀 macro F1 차이의 대응 구간을 보고합니다. 판정 보류 여부와 관계없이 모든 최종 글 쌍을 포함하고, 해시와 정확한 ID를 고정 기록 및 릴리스 보고서와 대조합니다. 모델 추론, 파라미터 학습이나 재선택은 수행하지 않습니다. 원시 손실 비교는 별도로 유지하며 보정된 차이의 구간에는 입력 순서와 보정의 효과도 포함됩니다.

이 구간은 제공된 데이터, 관찰한 문서 그룹과 학습 seed 한 번에 대한 조건부 구간입니다. 학습 seed 반복, 새 저자나 새 도메인의 변동을 추정하지 않습니다. 그룹의 교환 가능성을 가정하며 bootstrap이 과거 데이터 사용이나 측정하지 않은 유사 문서의 의존성을 제거하지도 않습니다. 평가 후 불확실성을 보고하는 용도이며 배포 모델이나 판정 규칙을 바꿀 수 없습니다.

## 실행 환경과 재검증 증거

합성 데이터 테스트는 그룹 분리, 지수가 0일 때의 CE 동등성, gradient, 보정과 파일 무결성 같은 구현 조건을 확인합니다. 저장 모델 재검증은 실제 공개 가중치를 라벨이 있는 데이터에서 다시 실행합니다. 재학습은 별도의 작업이며, 테스트를 통과했다는 사실만으로 다른 환경에서도 실제 모델 예측이 재현됐다고 주장할 수 없습니다.

완료한 Large 실행 가능성 검사는 T4 하나에서 유효 배치 update 40회를 시도해 39회 성공했고, FP16 overflow로 1회 건너뛰었습니다. 시도 시간 중앙값은 5.136초, 최대 할당 메모리는 6.09 GiB였으며 OOM 재시도는 없었습니다. 검사 가중치는 모두 폐기했고 보정이나 최종 추론을 수행하지 않았습니다. 실행 가능성의 근거이며 정확도, F1이나 전체 학습 시간의 보장은 아닙니다. 당시의 3-epoch 직렬 추정과 이후의 병렬 규칙은 [`reports/capability/summary.json`](../reports/capability/summary.json)에 구분해 기록합니다.

관찰한 각 재검증의 운영체제, Python과 고정 패키지 버전을 기록합니다. 같은 컴퓨터의 두 운영체제는 같은 물리적 호스트입니다. CPU 속도는 같은 예시, 입력 길이 정책, 배치 크기와 스레드 수에서 측정하고 예열과 반복 횟수를 공개합니다. AB 한 번의 추론과 두 번 실행하는 대칭 추론을 구분합니다. 파일 크기와 지연 시간은 측정한 특성이며 최종 정확도를 대신하지 않습니다.
