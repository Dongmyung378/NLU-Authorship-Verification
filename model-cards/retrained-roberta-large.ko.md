# 재학습한 RoBERTa-Large

[English](./retrained-roberta-large.md) | [실측 결과](../docs/results.ko.md) | [학습](../docs/training.ko.md) | [최초 모델](./roberta-asymmetric-loss.ko.md)

Dongmyung Park과 Juho Kim이 2026년 2월부터 5월까지 공동 개발한 프로젝트의 RoBERTa-Large 구조를 유지했습니다. 고정한 같은 사전학습 초기화에서 새 체크포인트 두 개를 학습해 교차 엔트로피와 최초 직접 구현한 이진 비대칭 focal 목적함수를 비교했습니다. 최초 과제 학습 가중치는 재사용하지 않았습니다.

## 구조와 대응 학습

| 항목 | 실제 구성 |
|---|---|
| 기반 모델 | `FacebookAI/roberta-large` |
| 사전학습 버전 | `722cf37b1afa9454edce342e7895e588b6ff1d59` |
| 과업 | 영어 글 쌍의 저자 동일성 분류, 클래스 2개 |
| 파라미터 | 355,361,794개, FP32 저장 |
| 기반 구조 | 24개 층, 폭 1,024, attention head 16개 |
| 최대 입력 | 합산 512토큰, longest-first 잘라내기 |
| 학습 / 선택 / 보정 / 최종 평가 | 21,972 / 3,139 / 1,569 / 4,708쌍 |
| 학습 시드 | 378, 한 번 |
| Microbatch / 유효 배치 | 2 / 32 |
| 학습률 / weight decay | 0.000005 / 0.01 |
| 완료한 학습 | 손실별 6 epoch, 공통 대응 epoch 상한 |
| 저장한 최적 체크포인트 | 손실별 5 epoch |
| 학습 정밀도 | FP16 순전파, FP32 손실, gradient checkpointing |
| Overflow로 생략한 update | CE 7회, custom focal 6회 |
| 체크포인트 가중치 | 각각 1,421,495,360바이트, 약 1.42 GB / 1.32 GiB |

Worker 두 개는 초기화 해시 `ffe7ba5e9107a846e6c9303dc914893535a441412c12fee323111b17a754acd3`, 기록한 6개 epoch 스케줄 해시와 최적화 조건을 공유합니다. 각각 배정받은 T4 하나를 사용했습니다. 공통 epoch 동기화와 patience 3으로 완료한 epoch 수를 맞추되, 손실마다 자신의 최적 선택 체크포인트를 저장했습니다. FP16 scaler overflow가 발생하므로 같은 시도 순서가 성공한 update 수까지 같다는 의미는 아닙니다.

Custom focal은 두 클래스 softmax 확률에서 `-(1-p_y)^gamma_y * log(p_y)`를 계산하고 `gamma_0=2`, `gamma_1=1`을 적용합니다. 최초 이름을 보존해 실행 식별자는 `custom_asl`입니다. 확률 clipping을 사용하는 발표된 다중 레이블 sigmoid ASL과는 다른 구현이며, 서로 다른 목적함수의 손실 크기를 비교해 정확도 향상을 주장하지 않습니다.

## 모델 선택과 고정 평가

최종 평가 전에 보정값을 고정한 파이프라인의 선택 macro F1은 CE 0.801199, custom focal 0.799145였습니다. 대안이 필요한 +0.002 개선에 도달하지 않아 배포용 Transformer는 CE를 유지합니다. 두 모델 모두 선택 집합에서 결정한 대칭 평균 logit 추론과 별도 보정 집합에서 적합한 보정값을 사용합니다.

| 모델 | 원래 AB F1, 임계값 0.5 | 고정 macro F1 | 정확도 | 정답 |
|---|---:|---:|---:|---:|
| CE, 배포용 | 0.807724 | 0.808383 | 80.8624% | 3,807 / 4,708 |
| Custom focal, 보존한 비교 모델 | 0.808153 | 0.815170 | 81.5208% | 3,838 / 4,708 |

판정 보류 사례의 내부 이진 예측까지 포함해 최종 글 쌍 전체를 평가한 결과입니다. 이후 관찰한 focal의 우위로 고정한 배포 선택을 바꾸지 않았습니다. 최초 개발 F1 0.8348과는 평가 조건이 달라 통제된 전후 비교가 아닙니다. 입력 순서, 보정, 구간과 조건부 불확실성은 [결과](../docs/results.ko.md)와 [평가 규칙](../docs/evaluation.ko.md)에 설명합니다.

보정으로 CE ECE는 0.045364에서 0.024756, focal은 0.057828에서 0.033591로 감소했습니다. CE가 판정한 비율은 82.3067%이고 해당 정확도는 86.3742%이며, focal은 82.8802%에서 86.6735%입니다. 모두 80% 이상 처리하며 정확도 90% 이상을 확보하는 목표에는 미달했습니다. 이를 보고 임계값을 다시 맞추지 않았습니다.

대응 학습 parent는 23,025.254초, 즉 실제 경과 6.3959시간이 걸렸습니다. 준비와 동기화 대기를 포함한 배정 worker 합산은 45,993.036초, 즉 12.7758시간입니다. 고정 평가까지의 전체 wrapper는 실제 경과 7.5475시간입니다. 자체 측정으로 계정의 공식 할당량 차이를 이 작업의 사용량으로 간주하지 않습니다. 전체 실행의 제한된 GPU profile 단계에서는 worker별 할당 메모리 6.09 GiB를 기록했으며, 모든 epoch의 최대치나 CPU 프로세스 메모리 측정은 아닙니다. [학습 보고서](../reports/training-report.json)와 [자원 측정](../reports/training/gpu-profiles.json)에 근거를 제공합니다.

공개 모델 전달과 새 CPU 환경의 실제 재검증을 [재현 안내](../docs/reproduction.ko.md)에서 별도로 검증했습니다. Large 두 체크포인트 모두 Windows와 Ubuntu WSL2에서 4,708쌍 전체 추론을 완료했으며 분류, 판정 보류, F1과 정확도가 일치했습니다. 두 모델 모두 두 환경에서 변경하지 않은 `1e-5` GPU 참조 확률 비교에는 실패했습니다. [CPU 요약](../reports/cpu-reproduction.json)에 이 판정과 완료한 지연 시간 및 전체 프로세스 메모리 측정을 함께 보존했습니다. 두 로컬 환경은 같은 물리적 컴퓨터를 사용합니다. Large 대칭 추론에는 순전파 두 번이 필요하며, 문체 앙상블과의 실제 자원 비용 비교는 [실측 결과](../docs/results.ko.md)에 제공합니다.

## 사용 목적과 한계

제공된 영어 글 쌍 라벨을 예측하는 연구 및 포트폴리오 시연용 모델입니다. 저자와 도메인 ID가 없고 과거 데이터 사용 이력을 공개하며, 의미가 유사한 문서의 분리는 확인하지 못했습니다. CE의 50단어 미만 구간 F1은 0.741795이며 200단어 이상은 사례가 5쌍뿐입니다. 최종 4,708쌍 중 197쌍은 잘라내기의 영향을 받습니다. 학습 한 번으로 시드별 안정성을 확인하거나 임의의 글에 대한 법과학적 신원 판단을 입증할 수 없습니다.
